# API compatibility

LLM Proxify implements a **subset** of the OpenAI HTTP API:

| Method | Endpoint | Behavior |
| --- | --- | --- |
| POST | `/v1/chat/completions` | JSON or live SSE, including `[DONE]` |
| GET | `/v1/models` | First available server's model list |
| GET | `/v1/models/{model}` | Retrieve model from the selected server |
| GET | `/healthz` | Public liveness only: `{"status":"ok"}` |
| GET | `/health` | Queue and backend counters; requires auth when configured |

Requests and upstream response bodies are forwarded without rewriting JSON fields
or SSE events. Tool calls, structured output, multimodal messages, usage chunks and
vendor extensions work **when supported by the upstream**. The proxy checks valid
JSON, a non-empty model string, a non-empty messages array and a boolean stream
flag. Full model-specific schema validation belongs to the upstream.

Unsupported routes return 404. Wrong methods return 405. Local errors use
`{"error":{"message":"...","type":"...","param":null,"code":"..."}}`.
Upstream HTTP status, body, Content-Type, Retry-After, X-Request-ID and rate-limit
headers are preserved. Invalid upstream responses are not repaired or certified.
No redirects are followed. Content-Encoding and Content-Length are regenerated by
the transport, not blindly copied after decompression.

The model list is not merged, and the requested model is not rewritten. Use a pool
of equivalent replicas serving the same model ID and credentials. There is no
model-based routing. Responses, audio, images, files, embeddings and stored chat
completion management are outside this release's scope.

## Failover and limits

Available servers with fewer active requests are preferred; ties rotate fairly.
All supported upstream requests, including model discovery, use the same slot
limits. A slot remains reserved until the response finishes or the client disconnects.
Queues and request bodies are bounded.

Network errors, HTTP 429 and HTTP 5xx trigger failover and cooldown. Other HTTP 4xx
are returned immediately, without retrying. Each backend is attempted at most once
per incoming request. If the last backend returns an HTTP error, that response is
preserved; if all attempts fail at the transport layer, the proxy returns 502.
A full queue returns 429; an exhausted forwarding deadline returns 504 (408 if
the incoming request body did not arrive in time). These statuses
also apply to model discovery; failures are never disguised as an empty model list.

Failover stops once response headers/data reach the client. A stream interrupted
by a disconnect, upstream failure or deadline is closed; no fake `[DONE]` is added.
The total deadline includes reading the incoming body, queue waiting, attempts and
response streaming. The socket timeout also limits inactive upstream operations.

Retries can duplicate inference work if an upstream processed a request but its
response was lost. Clients (including the OpenAI SDK) may have their own retries;
use `max_retries=0` to let only this proxy retry.

One process manages one pool. Running several containers or ASGI workers creates
independent slot limits; do not use that to enforce a global one-request-per-GPU limit.

## Verification

Tests use conforming mock JSON/SSE responses, the official Python SDK with strict
response validation, and a real local HTTP streaming connection. They check byte
preservation, auth, errors, retries, concurrency, deadlines and disconnect cleanup.
They do not certify every OpenAI endpoint or every third-party model server.
